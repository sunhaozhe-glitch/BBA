暂停与“确定无效果”的边界：permit 已过期、或 runtime/identity 代际已前移时，本受管 worker 在发送点已不可能完成本次发送，仍按确定无效果处理（释放 send lock、slot、claim 与当日 quota，可重试）；该证明只覆盖本 worker，不证明旧 owner 或其它进程已被隔离。暂停/取消是策略性停止，在飞窗口内不能自证“未发生”，因此一律留为 unknown，由既有只读对账收敛。

### F1：终态任务的关联 leave 与 passive leave 口径不一致

### 5.1 F1 终态归并：只落事实、inbox 与晚到审计

终态任务 = `CANCELLED` / `SUCCEEDED` / `PARTIAL` / `FAILED`。关联路径的终态判定放在成员状态分派之前（`joined` 与 `not_joined` 都先经过该门）；passive 路径在 `invalidatePassiveLeave` 内使用同一终态集合。`not_joined` 到达终态任务时：

- 成员投影更新与 `inbox.apply_state='applied'` 在成员事实落库路径完成；
- 关联路径追加 `membership.late_observed`（携带 `state='not_joined'`）；passive 路径由 `invalidatePassiveLeave` 追加 `membership.passive_leave_terminal`（`read_only=true`）；
- 同一事件重放不重复审计；
- **不**撤销 valid result、**不**释放/清空 goal slot、**不**解除 target claim、**不**把 subtask 转 `RECONCILING`、**不**改写已闭卷的成功计数；
- 不自动退群、不自动重发、不重开终态。

活跃任务（非上述四态）的关联与 passive leave 行为保持不变：valid result 置 `valid=false`、slot 回收、claim 解除、subtask 转 `RECONCILING`、写 `result.invalidated` 与只读对账。关联路径与 passive 路径使用同一终态判定，不允许只修其中一条。

仓内回归为 `TestFourthTerminalLeaveHistory`（`backend/internal/taskengine/fourth_review_test.go`），覆盖 4 个终态 × 2 条路径（correlated / passive）共 8 个子用例；每个子用例重放 leave 两次，断言：

### 5.2 F2 并发 observation 幂等与冲突

写入路径改为“插入后仲裁”：`INSERT ... ON CONFLICT DO NOTHING` 返回 0 行时，在同一事务内用独立语句（新快照，可见已等待完成的胜出者）按 `event_id` 优先、否则按 source-position 重读持久行，并比较 digest：

- 同 `event_id`、同 digest：幂等成功，不重复应用；
- 同 `event_id`、不同 digest：`conflict_kind='event_digest'`；
- 同 source-position、不同 `event_id`：`conflict_kind='source_position'`；
- 后两类都先向 `core.observation_conflict` 追加一条冲突审计（incoming/stored 的 event、digest、payload，外键指向胜出的 inbox 事实），**提交后**才返回 `OBSERVATION_DIGEST_CONFLICT`；不静默覆盖首笔事实，不把冲突记为“已应用”，也不让裸 `23505` 逃逸；

### 5.3 F3 本地停发与外部未决分层

- 本地停发完成的判定只看本地是否仍可能发起或继续在飞发送：没有仍可能被合规 dispatcher 使用的 issued permit、没有仍处于 `DISPATCHING` 的 execution、没有进程内登记的活跃本地发送，并已检查 bridge 状态。实现使用进程本地的活跃发送登记（`activeLocalDispatches`，按 workspace/task 计数），登记覆盖受管 worker 的整个发送生命周期：即使 `RecoverDispatching` 已把数据库 operation 从 `DISPATCHING` 改为 `UNKNOWN`，只要 adapter 调用仍在本次进程内运行，该登记仍阻止暂停落定与恢复。
- 外部 `pending`/`unknown`（含 `confirmed_submitted` 与其保留的 slot/claim/action lock）属于“外部未决”，保留观察，但不再阻塞 `PAUSING → PAUSED`；保留的 action lock 仍会阻止同账号同动作类别的新发送，这是发送互斥而不是本地停发未完成。
- `resume` 在 `PAUSED`/`PAUSING`/`BLOCKED` 上仍重验 import、baseline、deadline、scope、账号；外部未决不阻止恢复，但恢复**不得**把 `pending`/`unknown` 改回 `QUEUED`、不得重新签发发送、不得重置 retry、不得释放其 slot/claim。既有未决工作保持原状态、零重试，新工作只能用剩余 free slot。
- 该登记是**进程本地**证明，不是生产进程管理器、跨进程/跨机、旧 owner 或全局单 writer 隔离认证。旧 worker 未被证明停止时仍禁止 owner 迁移，并按 bridge 崩溃语义进入 `BLOCKED`（D5、`02:262`）。
- 若负责人选择“整任务等待外部终结”的更保守语义，必须有书面裁决并同步修改规范与界面；不得在保持原语义的情况下偷偷释放 slot/claim，也不得让任务永久卡在 `PAUSING`。

仓内回归位于 `backend/internal/taskengine/fourth_pause_test.go`，五个测试：

| `TestFourthPauseSettlesPendingExternalAndResumes` | `submitted`/`confirmed_submitted` 外部未决：pause 直接落 `PAUSED`；resume 回 `RUNNING` 且不重新入队、不改写 execution；剩余 free slot 可用于其它 target；未决的 slot/claim/quota/adapter 计数保持不变 |
| `TestFourthPauseUnknownHeldLockLocalStopResume` | `UNKNOWN` 保留 action lock：pause 落 `PAUSED`、resume 回 `RUNNING`；`UNKNOWN/unknown` 不被改写；同账号因 held lock 仍 `NO_CAPACITY`；无重试、无重发 |

## 第五轮语义基线（供实现与复审共用）

### 终态事实分层

- 历史计数与当前成员事实分离：终态任务的晚到权威 `not_joined`（关联或 passive）只更新成员投影、inbox 与晚到审计（关联 `membership.late_observed`，passive `membership.passive_leave_terminal`）；已闭卷的 valid result、slot、claim、subtask 均不改写。
- 终态任务的晚到 `joined` 仍只写审计（既有行为），不重开、不补发、不计功。
- 活跃任务的失效语义不变；`result.invalidated` 仍是活跃路径的正当审计，不用于终态。

### 本地暂停与恢复

- 暂停分两层：**本地发送静止**（不再签发新 permit、在飞发送按下述“消费后暂停”处理）与**外部未决**（已提交待审批、UNKNOWN、待对账）。
- `PAUSING → PAUSED` 只要求本地发送静止；外部未决不阻塞落定，也绝不因落定而释放其 slot/claim/配额。
- 本地发送静止由三部分判定：无 `DISPATCHING` execution、无仍可用的 issued permit、无进程内登记的活跃 adapter 调用。登记按 workspace/task 计数，覆盖 adapter 调用的整个生命周期，即使恢复已把数据库 operation 改为 `UNKNOWN`。该证明仅限本进程的受管 worker，不认证生产进程管理器、跨进程/跨机、旧 owner 停止或全局单 writer。
- `resume` 不得把外部未决改回 `QUEUED`、不得重发、不得重置 retry；未决保留原状态与占用，恢复后的新工作仅使用剩余容量。
- 暂停/取消命中 permit 已消费、adapter 尚未调用的复验窗口时，该 worker 禁止进入 adapter，并记为 `UNKNOWN/unknown`，保留 send lock、slot、claim 与当日 consumed。若 adapter 已进入，暂停不会撤回已飞出的请求；等待真实回执或权威观察收敛，调用未返回时仍阻止本地暂停落定。两种情形均不自动重试。
- 只有 permit 过期、subtask 改派/不可派发、账号凭据或代际不符这类“本受管 worker 已不可能完成本次发送”的拒绝，才记为确定无效果并释放占用；且其证明范围仅限本 worker（见下）。

### UNKNOWN 的收敛边界

- UNKNOWN 不是成功，也不能证明发送未发生；它禁止重发：一个 `gateway_operation` 只能调用一次 adapter，恢复、超时与旧 worker 唤醒都不得补发。
- UNKNOWN 也不是不可收敛的终态。两条既有收敛路径仍然有效：权威成员观察可把 execution 收敛为 `OBSERVED`；adapter 已实际调用而回执迟到时，真实回执可把 `UNKNOWN` 落账为 `OBSERVED`。收敛只改变证据与结果，**不重新授权发送**。
- 报告中任何“恢复提交的 UNKNOWN 是终态、任何观察都不可改状态”的表述作废；正确表述是“UNKNOWN 禁止重新发送，但可由权威观察或真实迟到回执收敛”。

| 6 | `ACCOUNT_RESTRICTED` | 账号 `control_state` 非 `active`，或 `risk_state` 非 `clear`，或 `connection_state` 非 `online`，或 `login_state` 非 `logged_in` | 策略性停止 | 同第 3 类 |
| 7 | `ACCOUNT_RESTRICTED` | 凭据不活跃、账号 runtime 与 actor runtime 不符、账号/凭据/载荷 `owner_epoch` 不一致、`identity_status` 非 `verified` | 确定无效果 | 同第 1 类 |
| 8 | `ACCOUNT_RESTRICTED` | gateway 记录的 identity generation 与当前 generation 不符 | 确定无效果 | 同第 1 类 |

补充边界：

- 第 6 类是本轮 `bridge.go` 生产改动的一部分：原 `ACCOUNT_PAUSED` 分支被 `ACCOUNT_RESTRICTED` 取代，并扩大到 `risk_state`/`connection_state`/`login_state`。另在 `Dispatch` 的 permit 消费前最终就绪读中，同一组账号状态与 runtime/identity/owner/generation 一并校验，任一不符即返回 `ACCOUNT_RESTRICTED`，连 permit 消费都不进入。这两处门禁都已计入第八轮 21/27 文件指纹。

- 第 1、2、5、7、8 类记录为“确定无效果”，只对本受管 worker 成立；不影响其它仍持有旧 permit/连接的进程（D5 未切换、生产 writer 未认证）。
- 读取、加锁或数据库错误不是拒绝分类：`revalidateBeforeSend` 返回错误，adapter 不被调用，事务回滚；已消费的 operation 仍停在 `DISPATCHING`，由恢复与只读对账处理，不进入重试。
- 上表是 `revalidateBeforeSend` 的全部分支。任何新增分支必须同时更新本表与回归，避免再次出现“两份不完整分类列表”。

### 代际漂移的证明范围

identity/runtime/owner epoch 前移导致的 `ACCOUNT_RESTRICTED` 只证明**本受管 worker 在发送点被拒绝**，不证明旧 owner 已停止、旧连接已关闭或账号已全局隔离。`02:249` 明确 fencing 只约束受管理 bridge，不能撤回已飞出的请求；`02:262` 要求无法证明旧 owner 不会发送时进入 `BLOCKED`，而不是“提升 epoch 就安全”。因此：

- 不得用本拒绝推断生产 owner 迁移或全局单 writer 已认证；
- 旧 runtime 未隔离时，禁止账号 owner 迁移；
- 本阶段没有生产进程管理器、跨机隔离或第三方 writer 枚举证据。

## 进程级证据（首次交付的两项缺口，第四轮已复核）

两项证据都使用真实子进程（`os/exec` 重执行测试二进制进入 `TestRemediationProcessChild`），父进程只通过数据库与进程退出信号观察；adapter 内部 sleep 不计作“调用前暂停”的证据。

### A. adapter 返回后、回执落账前 `SIGKILL`

`TestRemediationKillAfterAdapterBeforeReceipt`，退出码 0：

```text
SIGKILL child <pid> after adapter return; receipts=0; recovery=UNKNOWN with slot/claim/lock retained; adapter_calls_total=1
```

做法与断言：子进程 Dispatch 进入 adapter 并写外部 marker 后返回；fixture 库上的 `BEFORE INSERT ON bridge.outbox` 触发器 `pg_sleep(5)` 把“回执落账”这一真实写入拉宽。父进程等到 adapter marker 存在且 `pg_stat_activity` 显示该 `INSERT INTO bridge.outbox` 正在执行后 `SIGKILL`。落库状态为 `bridge.outbox=0`、gateway `DISPATCHING`、execution `DISPATCHING`、permit `consumed`；随后 `RecoverDispatching` 返回 1，gateway/execution 转 `UNKNOWN`，send lock、slot、claim 全部保留，result=0；再调 `Dispatch` 返回持久化状态且 adapter 调用 0 次；24h 后 `ReconcileTimeouts` 返回 1 且 retry=0。

### B. permit 消费提交后到发送前长暂停

`TestRemediationLongPauseAfterConsumeNeverSends`，两个子用例退出码 0：

```text
paused worker refused with PERMIT_EXPIRED; adapter_calls=0; holds released only as definite no-effect
paused worker refused with ACCOUNT_RESTRICTED; adapter_calls=0; holds released only as definite no-effect
```

做法：父进程先持有该 subtask 行锁，子进程完成 consume 提交后必须进入 `revalidateBeforeSend` 的 subtask 行 `FOR UPDATE`（阻塞语句只锁 `core.subtask` 一张表），因此被确定性地卡在“已消费、未发送”窗口；父进程确认 `permit.state='consumed'`、adapter marker 不存在后，分别让 permit 过期或把 `identity_generation` 前移，再释放行锁。

发送前复验要求：permit 仍是本次消费且未过期、task 不处于暂停/取消/终态、账号 control 为 active、subtask/attempt 未被改派、runtime/owner epoch/credential/identity generation 仍匹配。各拒绝的完整条件、落账与占用处理见「发送点复验拒绝分类（穷举）」。这里的暂停拒绝发生在 adapter 尚未进入时；已经进入 adapter 的请求不可由暂停撤回，真实迟到回执仍可落账，不把它误称为已取消发送。

该门禁的红测：临时移除调用后，两个子用例在 0.48s 内均失败于 `child entered the adapter before the pause was released`，证明测试确实覆盖“旧 worker 会发送”这一行为，而不是恒真断言。恢复调用后转绿。

## D2 / 状态闭包（第五轮口径）

- `submitted`、`pending`、`unknown` 不成为成功结果或 retry；可能仍有效时保留 slot、claim、account lock 与配额。
- bridge 只允许一次 adapter 调用；dispatch 崩溃落 UNKNOWN；恢复与 24h 超时只产生只读对账，不重发、不释放业务占用。
- 过期 permit 清理仍限定为未消费、已过 DB expiry、execution 仍为 `CREATED`/`ACCEPTED` 的情形。
- consume 提交后到 adapter 调用前的复验门禁保留。拒绝分类以「发送点复验拒绝分类（穷举）」表为准，不得只引用其中两类；其中“确定无效果”仅指本受管 worker 已不可能完成本次发送，不扩张为全局隔离。
- confirmed 但尚无 membership result 的窗口态保留 slot/claim，并进入 24h 只读对账（`reason=membership_result_missing_24h`）。
- 活跃任务收到权威 `not_joined`（关联或被动）时，该账号在此 target 的 result 失效、slot 回池、claim 解除、subtask 转 `RECONCILING` 并写对账事件；不自动退群、不自动重发。
- result closure 仍要求 confirmed execution、当前 scope、匹配且 consumed 的 permit、权威新 membership；result 证据不可删除。
- 本地停发与外部未决分层：`PAUSING → PAUSED` 只要求无仍可能被合规 dispatcher 使用的 issued permit、无 `DISPATCHING` execution、无本进程登记的活跃 adapter 调用且已检查 bridge 状态；进程内登记覆盖 adapter 调用全程，恢复改写 `UNKNOWN` 不提前释放。外部 `pending`/`unknown` 不阻塞落定，也不因落定被释放。恢复不得把 pending/unknown 改回 `QUEUED`、不得重发、不得重置 retry。该证明仅限本进程，不认证生产/跨机/旧 owner 隔离。
- 暂停/取消命中已消费、尚未调用 adapter 的复验窗口时，阻止该 worker 发送并落 `UNKNOWN/unknown`，保留 send lock、slot、claim 与当日 consumed，不自动重试。已经进入 adapter 的请求不因暂停被撤回，须等待真实回执或权威观察；只有本受管 worker 的确定无效果拒绝才按上表释放占用。
- 被动（无 operation 关联）权威 `not_joined` 与关联路径使用同一终态判定：活跃任务撤销已计数 result、slot 回池、claim 解除、subtask 转 `RECONCILING`；终态任务（`CANCELLED`/`SUCCEEDED`/`PARTIAL`/`FAILED`）只更新成员事实、inbox 与只读审计，不改写已闭卷的 result/slot/claim。
- 占用例外必须晚于本次执行：confirmed 且尚无 result 的执行，只有 `observed_at >= COALESCE(execution.observed_at, execution.started_at)` 的权威 `not_joined` 才能解除 slot/claim；“本次发送之前的缺席”不构成本次效果的解除依据。
- 恢复提交的 UNKNOWN 不得重新授权发送：发送点在 adapter 调用前重验 gateway/execution 仍为 `DISPATCHING`，已隔离的 operation 不会被醒来的旧 worker 补发。UNKNOWN 不是不可收敛的终态：权威观察或真实迟到回执仍可使其收敛为 `OBSERVED`，但收敛不重新授权发送。
- identity/runtime/owner epoch 漂移只证明本受管 worker 在发送点被拒绝，不证明旧 owner 已停止或账号已全局隔离；旧 runtime 未隔离时禁止 owner 迁移。
