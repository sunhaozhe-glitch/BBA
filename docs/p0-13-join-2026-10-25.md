## 实现

### 1. fixture 回归：`backend/internal/taskengine/p013_test.go`

1. `TestP013SubmittedRequestRefThenConfirmedMembership`
   - adapter 返回 `submitted/confirmed_submitted` 和 `RequestRef`；
   - 断言 execution 持久化 `external_request_ref`，gateway `response->>'request_ref'` 同值；
   - 断言 submitted 不产生 valid result、不释放 reserved slot、不解除 active claim；
   - `join_request.observed/approved` 仍不记 result；
   - 只有 `membership.observed/joined` 才使 execution 转 confirmed、写 valid result、fulfilled slot、membership joined、`result.confirmed` 审计。
2. `TestP013RejectedStopsWithoutRetry`
   - `join_request.observed/rejected` 落 `rejected/confirmed_rejected`；
   - subtask `FAILED`、零 retry、adapter 只调用 1 次、slot 回 free、`execution.rejected` 审计 `retry=false`。
3. `TestP013ChallengeAfterPermitStopsBeforeAdapter`
   - permit 签发后账号被置 `challenge_required`；
   - `Dispatch` 返回 `ACCOUNT_RESTRICTED`，adapter 0 次，execution 仍 `ACCEPTED`，permit 仍 `issued`，零 retry，account send lock 保留。

`request_ref` 的写入语句仍位于 `bridge.persistOutcome`，本轮没有改这条语句本身；但 **`bridge.go` 本轮确有生产改动，不能写成“未改生产代码”**。改动是两处发送前门禁加一处错误码变更：

- `Dispatch` 在 permit 消费前的最终就绪读新增 `control_state`/`risk_state`/`connection_state`/`login_state` 四项校验；与 runtime、`identity_status`、owner epoch、identity generation 任一不符即返回 `ACCOUNT_RESTRICTED`，不进入消费与 adapter。
- `revalidateBeforeSend` 的账号状态门禁在原有 `control_state` 之外新增 `risk_state=clear`、`connection_state=online`、`login_state=logged_in`，并把原 `ACCOUNT_PAUSED` 分支改为 `ACCOUNT_RESTRICTED`（`quarantine`，策略性停止）；凭据、runtime、owner epoch、identity 与代际不符的 `ACCOUNT_RESTRICTED` 确定无效果语义保持不变。

测试 3 锁定的正是新增门禁：permit 签发后账号进入 `challenge_required`，`Dispatch` 在 adapter 前返回 `ACCOUNT_RESTRICTED`。为证明 `request_ref` 断言不是恒真，在隔离副本中把 `external_request_ref` 参数替换为 `nil` 后，`TestP013SubmittedRequestRefThenConfirmedMembership` 以 `execution=... ref=""` 失败；恢复后通过。该突变只用于测试敏感性，不进入交付代码。

### 2. 运行入口：`backend/cmd/p0-13-join/main.go`

顺序固定为：

1. 读取 `state.json`，要求唯一 `label=36374700`、WebUI `6211`、OneBot `3211`，否则拒绝绑定；
2. 打开一次性数据库并执行 `Migrate`，先插入 workspace/principal/account/runtime credential fixture 行；这些数据库 fixture 在**任何 HTTP 之前**完成，不属于“预检后建立 task”；
3. `get_login_info`：校验 `user_id=36374700`；
4. `get_status`：`online` 与 `good` 都必须是 JSON 布尔 `true`；缺失、`null`、字符串或 `false` 一律 `STOP_STATUS_INVALID`；
5. `get_group_list`：写前 baseline 重读；每条记录必须是 `group_id` 数字串且 `group_name`、`member_count`、`max_member_count` 完整，混合/不完整记录直接 `STOP_BASELINE_FAILED`，不得跳过坏记录后继续；
6. 目标已在 baseline → `STOP_BASELINE_ALREADY_MEMBER`，不认证 WebUI、不做预检、不创建任务；
7. 目标不存在 → WebUI `/api/auth/login` 获取短期 credential，再 `GET /api/Plugin/List` 做能力预检：要求 `code=0`、`pluginManagerNotFound=false`，且 `napcat-plugin-cleaner` 恰好一项、状态为 `active`；403/404/405/500、缺失或歧义证据一律 `STOP_CLEANER_UNAVAILABLE`，join 路由 404 不再被当作可用；
8. 预检通过后才建立任务 fixture：固定 target 审批、`CreateTask`（1 goal、1 target、1 attempt）、`ExpandFixedPage`、`CompleteBaseline`（完整 52 群）、`ControlTask start`、`Reserve`、`AcceptOperation`、`IssuePermit`；
9. `Dispatch` 调 cleaner adapter（只在此处写入）；adapter 把 `ok`/`result` 映射为 `SendOutcome`，只在 `raw.request_id`、`raw.request_ref`、`raw.req_id` 为字符串时取 `RequestRef`；`raw.requestId` 不是代码支持的键，真实回执的关联格式仍未证实；
10. `PumpBridgeOutbox` + `ApplyObservation` 落 bridge 事件；
11. 每次写入后立即原子重写并关闭 `steps.jsonl` 与 `requests.jsonl`（未声明电源故障级 fsync）；最后写 `summary.json`；
12. 写后重读群列表：最多两次（一次立即、一次 2 秒后，均在预算内）；目标出现才发送 `membership.observed/joined`，否则只记 pending，不伪造 confirmed。

所有 HTTP 目标在发请求前再次限制为 `127.0.0.1`/`localhost`；重定向一律拒绝；token 不写日志。WebUI 认证步骤不保存请求体或响应体，避免登录 hash/credential 进入证据。运行器回归位于 `backend/cmd/p0-13-join/main_test.go`，覆盖证据脱敏、群记录严格解析、`status.good` 布尔校验、cleaner 能力预检 fail-closed 与全运行重试上限。
