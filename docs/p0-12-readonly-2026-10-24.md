## 实现与本次修正

既有 `Store.ReceiveHeartbeat` / `RuntimeHandler` 已实现 `POST /v1/internal/runtimes/{id}/heartbeats`，成功为 202 + `HeartbeatEnvelope`。runtime/workspace/account/owner epoch 必须匹配。本轮按契约补齐四点：

- 收据持久化：`core.runtime_heartbeat` 保存 `accepted_at`、`account_version`、`control_state`、`next_action_at`；`core.heartbeat_idempotency` 把每个成功 key（含同事件别名 key）绑定到唯一心跳事实。同一 key + 同请求返回原收据；同 key 异请求、以及已回放过的别名 key 再改 payload，均返回 `IDEMPOTENCY_CONFLICT`，不新增审计事实。
- 序号判定：先按 `(owner_epoch, sequence)` 查持久事件；同源同 digest 复用原收据，异 digest 返回 `HEARTBEAT_SEQUENCE_CONFLICT`。owner epoch 前移后重新开启序号空间；陈旧投递只写 `stale` 审计、回显请求 sequence，不合并账号投影。
- 能力声明在 HTTP 层直接校验原始 JSON，再按 `contracts/schemas/common.json#/Capability` 检查必需字段、枚举、长度、UTC `Z` 时间与非空语义；生成类型解码后的零值不能洗掉缺失/null（`supported`、`fresh_read` 等），`[{}]` 不再被接受。
- `HEARTBEAT_SEQUENCE_CONFLICT` 经 `ContractError` 映射为 HTTP 409 + 稳定安全消息，不再落到 500 的 `request failed`。

applied 更新 connection/login/heartbeat/version，保留 control/next_action。`core.runtime_heartbeat` 与 `core.heartbeat_idempotency` 均为 append-only，schema 10，迁移只接受精确版本 10。fixture 全包验证包含原有心跳回归与新增别名/原始 schema 回归。
